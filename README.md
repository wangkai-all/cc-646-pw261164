# 设备租用 × 保养 重叠明细

把设备租用区间与保养区间加工成一张可分设备查询的重叠明细表。整套服务**零第三方依赖**：Node 22+ 内置
`node:http` + `node:sqlite`，前端是原生 HTML/CSS/ES 模块。

```bash
npm start          # http://localhost:3000
npm test           # 引擎 + 样本 + 接口测试（Node 内置 test runner）
```

首次启动会在 `data/app.db` 建库。页面右侧有四个内置样本，点「载入」即按步骤发布版本；
也可以把 CSV 贴进导入框，或直接在页面上增删改单条记录。

---

## 1. 口径

| 概念 | 规则 |
| --- | --- |
| 区间 | **左闭右开** `[start, end)`。`A.end === B.start` 的两段相接但不算重叠。 |
| 零长度 | 结束时刻必须严格晚于开始时刻，`end <= start` 直接拒绝（API 400、导入报行号）。 |
| 未结束 | 结束时刻为空表示仍在进行。**查询必须先固定截止时刻 `asOf`**，所有开放段在该时刻封闭为 `[start, asOf)`。 |
| 配对 | 每条租用记录 × 每条保养记录最多产生**一个**连续交集。多条保养同时覆盖同一租用段时，匹配明细逐对保留（会彼此交叠）。 |
| 覆盖 | 覆盖区是全部有效保养段在租用段内的**并集**，可切成多段；段内可跨多条保养记录，相接的保养段会合并但保留接缝与成员。 |
| 空档 | 租用段 ÷ 覆盖并集。**可以有多段**，时长按切段累加，绝不用「租用总长 − 配对总长」：配对总长含重复覆盖，直接相减会把重叠处算成空档。 |
| 重复覆盖 | `matchLength − unionLength`，单独展示为证据，不参与空档计算。 |

切的依据逐条记在匹配明细的 `reasons` 里（交集端点来自哪一侧、是否被截止时刻截断、是否完全包含等），
页面上点任意结果行都能看到。

## 2. 一致性：版本化发布

- 每条输入记录每次变更分配一个递增 `seq`；发布时读取快照 `maxSeq`，在同一事务里写入
  `result_versions`、`device_results`、`overlap_matches`、`overlap_gaps`、`equipment_index`。
- 一次发布一个版本号。版本内既包含本次重算的设备，也包含从上一版本整体复制的其余设备，
  所以**任何版本都是完整视图**；读者按 `version` 过滤，不会看到新旧混合或半套数据。
- 发布事务失败整体回滚（版本号不消耗），测试里用注入写库错误验证过。
- 截止时刻是加工口径的一部分：`asOf` 变化时开放段截断位置变化，因此会整库重算，
  不会拿旧截止时刻的结果凑新版本。
- 历史版本可回看与导出：`GET /api/versions/:v`、`GET /api/versions/:v/export`（JSON / CSV）。

### 只重建必要区间

变更只影响其所属设备（记录不能改挂设备）。设备内部再按租用段收敛：

- 保养记录新增 / 更正 / 撤回：只重算**与旧有效区间或新有效区间相交**的租用段，其余租用段明细沿用上一版本；
- 租用记录变更：只重算该租用段；
- 受影响的段一律从**当前输入**重新推导 —— 撤回保养后原先不存在的空档会重新出现，
  重叠区也可能被拆成多段，不存在「在旧结果上做减法」。

每次结果的 `incremental` 字段说明本次重算了哪些租用段、复用了哪些、原因是什么，页面版本列表会展示。
多设备时未受影响的设备整体复制到新版本（标记 `reusedAll`）。

## 3. 朴素扫描核对

`server/naive.js` 不复用任何加工逻辑：以分钟为粒度逐分钟判断是否被任一条保养覆盖，再合并相邻同状态分钟，
得到覆盖段 / 空档；配对重叠用双重循环逐对求交。它与引擎的 `intersect / mergeIntervals / 切段` 完全独立。

- 测试里对**四个样本的每一步**都做逐段比对（含长度字段）；
- 页面「朴素扫描核对」按钮调用 `GET /api/verify`，返回当前版本的逐段比对结果。

## 4. 样本

| 样本 | 覆盖场景 |
| --- | --- |
| 完全包含 | 保养段完全覆盖租用段；租用两端都落在保养内部。 |
| 多段重叠 | 三条保养彼此重叠 + 分离；含「缩短 → 撤回 → 恢复」三步，验证空档按新并集重切、重叠重新出现。 |
| 瞬间相接 | 保养恰在租用起点结束 / 终点开始（都不算重叠）；两条保养瞬间相接（合并但保留接缝）；未结束的租用与保养段按两个不同截止时刻封闭。 |
| 撤回更正 | 连续覆盖撤回中间一条后空档重现；再更正为拆分的多段保养，覆盖区被拆开。 |

`server/fixtures.js` 里同时有人工计算的 `EXPECTED`，与朴素扫描互相独立，防止两者以同样方式出错。

## 5. 页面

- 顶部固定截止时刻；「查询」在版本与截止时刻不一致时先按该时刻发布新版本，「全量重建」强制整库重算。
- KPI 卡片：租用总时长、未覆盖比例、重叠明细条数、覆盖并集、租用段覆盖状态分布。
- 每台设备：甘特式时间线。**每条保养记录单独一行**（不再互相遮挡），随后是租用行、覆盖与空档行；
  超出租用段被截断的一端画白色缺口。下方是匹配明细表与空档表。
- 点匹配行 → 追溯两侧记录 + 切段依据 + 同租用段的其它匹配；点空档 → 解释并集切段、列出两端相接的保养；
  点甘特条 → 编辑该记录或查看覆盖段。
- 记录表与甘特条都可直接更正 / 撤回，保存后自动只重建受影响区间并发布新版本。

## 6. API 速览

```
GET  /api/config                              默认截止时刻、最新版本
GET  /api/results                             每台设备最新发布结果摘要
GET  /api/versions                            版本列表（含输入快照 seq）
GET  /api/versions/:v/export[?format=csv]     整版本导出（分析仓友好）
POST /api/query     {asOf?, version?, equipmentId?, onlyWithGaps?, onlyWithOverlap?}
GET  /api/verify   [?version=&equipmentId=]   朴素扫描核对
POST /api/import    {text, asOf?, kind?, dryRun?}
POST /api/rentals | /api/maintenance           {equipmentId, recordNo, start, end?, asOf?}
PUT  /api/rentals/:id | /api/maintenance/:id  更正（也可用于恢复已撤回记录）
DELETE /api/rentals/:id | /api/maintenance/:id
POST /api/samples/:key | /api/samples/reset
GET  /api/samples | /api/equipment | /api/equipment/:eq/records | /api/equipment/:eq/result
GET  /api/audit
```

时刻一律按 UTC 解释与展示；带 `Z` / 偏移量的输入会被换算。CSV 列序为
`设备编号, 记录编号, 开始时刻, 结束时刻, 类型`，类型取 `rental` / `maintenance`（或 租用 / 保养），
缺省为租用；带表头时按列名识别，不带表头时按固定列序。
